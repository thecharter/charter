# 003 — Types and domains

**Status:** approved (Eric, 2026-11-06; Charter 1.0.0). Fixed by D2 (eFLINT `Spec.hs`, `StaticEval.hs`), D7, D13, D22, and D24. Implementation: compliant (`src/Charter/Resolve/Static.lean`); all conformance tests pass.

**3.1 Kinds.** A type is a `Fact`, an `Act`, a `Duty`, or an `Event`; `Bool`, `Predicate`, `Invariant`, `Var`, `Function`, and `Physical` declare facts and acts with the restrictions below. A `Fact` with no `Identified by` has the string domain. `test/spec/spec_003_1_default_string_domain.eflint`

**3.2 Domains.** A domain is `String`, `Int`, `Time`, `Duration` (009.2), `Money(CUR, SCALE)` or `Quantity(UNIT)` (3.14), an enumeration of atoms (`A, B`), of integers (`1, 2, 3` or `1..5`), of single-character strings (`'a'..'z'`), or a product of components (`a * b`). An enumeration is *enumerable*: `+x.` with `x` free creates every instance of the type; `String` and `Int` are not, and a free variable over them ranges over the instances that hold (004.7). `test/spec/spec_003_2_enumerations.eflint`

**3.3 Products and variables.** A product's components are variables: a type name with a decoration (`person1 * person2`). An application gives arguments positionally in component order or by name (`f(a = e, b = e')`); a component not given stays free and is bound by the surrounding construct. The wrong number of positional arguments is CHR011. A component named twice is one value in both positions (`Holder actor Claimant actor`); an application that gives it two different arguments is CHR036. `test/spec/spec_003_3_products.eflint`, `spec_003_3b_arity_error.eflint`, `spec_003_3c_repeated_component.charter`

**3.4 Primitive application.** A type with a primitive domain is applied to exactly one positional argument of that domain (`x(5)`); anything else is CHR018. `test/spec/spec_003_4_primitive_application.eflint`

**3.5 Built-in types.** Every program declares `int` (`Int`), `string` (`String`), and `actor` (`String`, the actor type). An `Act` or `Physical` without `Actor` has the component `actor`. Instances of built-in types hold only when assigned, like any other. `test/spec/spec_003_5_builtins_and_default_actor.eflint`

**3.6 Open and closed.** A type is closed unless declared `Open`. An instance of a closed type with no assignment does not hold. An instance of an open type with no assignment is *missing input*: if the type has assigned instances, a free variable ranges over those that hold; a direct question about an unassigned instance is CHR100 (Law 6: the world is input). `Extend Fact x Closed` closes an open type for good: a later `Extend … Open` does not reopen it; a type that was closed by default may be opened. An `Open` or `Closed` immediately followed by a declaration keyword begins the next declaration; a bare one is a clause of the current one (so `Fact p Identified by P` followed by `Open Fact o …` leaves `p` closed). `test/spec/spec_003_6_closed_default_false.eflint`, `spec_003_6b_open_missing_input.eflint`, `spec_003_6c_open_with_assignments.eflint`

**3.7 `Var` and `Function`.** When an instance of a `Var` type is created, every other instance of the type is made false; of a `Function` type (a product of two components), every other instance with the same first component. A `Function` whose domain is not a product of exactly two components is CHR024: eFLINT ignores every assignment to one silently. `test/spec/spec_003_7_var_and_function.eflint`, `spec_003_7b_function_arity.eflint`

**3.8 Domain constraints.** `Where e` (or `When e` on a `Fact`) restricts the instances of a type to those whose components satisfy `e`. An element outside the constraint is not an instance: it is never created, enumerated, or derived. `test/spec/spec_003_8_where_constraint.eflint`

**3.9 Placeholders.** `Placeholder a For b` makes `a` another name for `b`, usable wherever a type name is, including as a differently named component of a product. An instance named through a placeholder is an instance of the aliased type (D13). A placeholder may name a type declared later in the same declaration block. `test/spec/spec_003_9_placeholder.eflint`

**3.10 Extending a domain.** `Extend Fact x Identified by …` (or `Domain …`) adds atoms to a string enumeration or integers to an integer enumeration, and turns `String`/`Int` into an enumeration. On a product type, or on an act, duty, or event, it is CHR014. `test/spec/spec_003_10_extend_domain.eflint`, `spec_003_10b_extend_domain_error.eflint`

**3.11 Redeclaration.** Declaring a type a second time replaces the first declaration entirely and warns CHR019. (B9, awaiting ruling: whether this becomes an error.) `test/spec/spec_003_11_redeclaration_warns.eflint`

**3.12 Static types.** Resolution gives every term one of: string, integer, boolean, or instance of a named type, and inserts the conversions of 010.4. A value where another type is needed, with no conversion, is CHR012.

**3.13 `Evidenced` facts and confidentiality (`D22`, `G3.2`).** `Evidenced Fact x … [Confidential [To r₁, r₂]]` declares an open external-world fact tracked over the four-valued epistemic lattice (`Established`, `Refuted`, `Unresolved`, `Conflicted`, 004.11) rather than halting with `CHR100` when unassigned (`T06`, `T07`). Optional `Confidential [To r₁, …]` marks evidentiary nodes for `x` confidential in `ReasonGraph` explanations for callers outside `[r₁, …]` without altering any legal verdict (`T43`). `test/spec/spec_003_13_evidenced_unresolved.charter`, `spec_003_13b_evidence_non_evidenced_error.charter`, `spec_003_13c_evidenced_conflict_and_finding.charter`

**3.14 Dimensional `Money` and `Quantity` domains (`D24`, `G3.4`).** `Money(CUR, SCALE)` (minor units at `10^SCALE` per unit of `CUR`, e.g. `Money(USD, 2)`) and `Quantity(UNIT)` are static dimensional integer domains (`Elem.int` at run time). Combining or comparing mismatched currencies, scales, or units is `CHR012` (010.12). `test/spec/spec_010_12_money_tiers_and_rounding.charter`, `spec_003_14_dimensional_mismatch_error.charter`

**3.15 Roles, status actors, and succession (`D36`, `#39`, `#40`, `#14`).** `Role r [For base] Is Atom` declares a singleton named-party role; `Role r For base Where c` declares a dynamic status role; `Role r For base First of A, B, … Unless u` declares an ordered succession role lowering to `Default`/`Exception` rules. Using a 1-component status `Fact` or `Role` as `Actor` requires the actor's status/role to hold for both lawfulness and validity and unwraps to `base` automatically. Reading a `Var` over an enumerated domain binds strictly to its holding instance (`#14`). `test/spec/spec_003_15_roles_status_actors_and_succession.charter`
