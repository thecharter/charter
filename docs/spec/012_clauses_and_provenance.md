# 012 — Clauses and provenance

**Status:** approved (Eric, 2026-11-06; Charter 1.0.0). Fixed by D4, D21, and Law 8. Implementation: compliant (`src/Charter/Core/Provenance.lean`, `src/Charter/Cli/Provenance.lean`); every statement has a passing conformance test.

Every norm carries its English, and the English leads (Law 8). A program names its authoritative document, quotes that document clause by clause, classifies every span of a clause into a register, and says which rule each normative span means. The checks below are run by `charter check` and at the end of `charter test`; each is a *claim* tagged *checked*, about *provenance*, and a failed one fails the file.

**12.1 Document (`D21`, `D40`).** `Document [ID] "path" [SHA256 "hex"] [Rank n]` names an authoritative English source relative to the program's file, optionally tagging it with a document identifier `ID` (for multi-document programs), pinning its expected 64-character lowercase SHA-256 content digest (`T39`), and declaring an explicit integer authority rank `n` (`docs/rfc.md` §4.5, `#73`: smaller integers outrank larger integers, e.g. `Rank 1` prevails over `Rank 2` between otherwise-unranked `Default`/`Exception` rules, surfaced in `check --verbose`, `doc`, and `explain`). `test/spec/spec_012_1_clauses_resolve.eflint`, `spec_012_9_multidoc_sha256.charter`, `spec_012_9b_stale_sha256_drift.charter`, `spec_012_9c_document_rank_lex_superior.charter`

**12.2 Clauses (`D34`).** `Clause ID [In DOC_ID] [Approved (HASH | "sha256-hex")]` declares a clause; `ID` is atoms, identifiers, and integers joined by dots (`DEF.01`, `T.2`), with an optional `/k` 1-based sentence index (`1.2/1`, `1.2/2`). Optional `In DOC_ID` binds the clause to a specific declared `Document DOC_ID`. A clause may either write inline `Text "…"` and register spans (`Norm "…" => …`, `Definition "…" [=> …]`, `Invariant "…" => …`, `Acceptance "…"`, `Commentary "…"`) or cite the authoritative document **by reference** (`Clause 1.3 [Register] [=> targets]`) without retyping its prose, extracting the paragraph under `# … 1.3` or numbered item `1.3` from `Document` (`D34`, `#35`). Declaring a clause id twice replaces the first. `test/spec/spec_012_1_clauses_resolve.eflint`, `spec_012_9_multidoc_sha256.charter`, `spec_012_11_cite_clause_by_ref_and_lock.charter`

**12.3 `From` (`D34`).** An act, duty, immunity, event, invariant, `Use`, `Property`, or scenario (D10, D34) may carry `From CLAUSE ["span"]`: the clause (and optional verbatim substring) it is the meaning of. The clause must be declared and, when `"span"` is given, must contain the quoted text. `test/spec/spec_012_1_clauses_resolve.eflint`, `spec_012_3b_invariant_from.eflint`, `spec_012_3c_scenario_from.eflint`, `spec_015_6_use_from_provenance.charter`

**12.4 Coverage.** A clause's spans, concatenated in order, reproduce its text exactly. `test/spec/spec_012_3_coverage.eflint`

**12.5 Norms are interpreted (`D34`).** Every `Norm` span names at least one formal target (or is cited via `From` on a rule), and every id a span names is a declared type (fact, derived fact, parameter, event, act, power, finding, amendment, duty, immunity, invariant), placeholder, or `Default`/`Exception` rule ID (`r` or `ty.r`); a ground-fact constructor target (`=> named(House, Anna)`) both cites `named` and asserts that ground instance in initial state (`#36`); an `Invariant` span names a declared `Invariant`; an `Acceptance`, `Definition`, or `Commentary` span may also name a declared `Scenario` or `Property` (D10, D34). `test/spec/spec_012_4_norm_needs_rule.eflint`, `spec_012_7_invariant_span.eflint`, `spec_012_3c_scenario_from.eflint`, `spec_012_11_cite_clause_by_ref_and_lock.charter`

**12.6 Every rule has its English.** Every declared act, duty, immunity, and invariant is named by some span, in a clause or by its own `From`. A rule with no span is the question and the rule is the answer under review (Law 8). `test/spec/spec_012_5_every_rule_named.eflint`, `spec_012_6b_amend_installs_provenance.charter`

**12.7 Verbatim and template blanks (`D34`).** Each clause's text occurs verbatim in the document (or in the document after substituting `{param}` / `{role}` blanks from declared `Param`s and singleton `Fact`s, `#59`). A document that cannot be read is a warning, not a failure, and the check is skipped. `test/spec/spec_012_6_verbatim.eflint`, `spec_012_13_template_blanks.charter`

**12.8 Approval and `charter approve` (`D34`).** Approvals may be recorded either inline via `Approved "<sha256>"` or in `charter.lock` via `charter approve [--lock] [--restamp] <file.charter>`, which records both `textSha256` and `rulesSha256` (so changing either the prose or a cited rule invalidates the approval as `STALE`, `#23`, `#32`, `#35`). The English is never edited to fit a rule, and an `Approved` value is never copied to silence the check (`AGENTS.md`). `test/spec/spec_012_2_approved_hash.eflint`

**12.9 Tracing and Markdown anchors.** `charter trace <clause> <file>` prints the clause's span table: register, text, and the rules each span means, with the document tag, approval state, SHA-256 digest, and legacy FNV-1a hash. `charter build` records each clause's nearest preceding Markdown heading (`# ...`), 1-indexed line, and surrounding-context SHA-256 fingerprint in `Artifact.SourceManifest`, keeping verbatim grounding resilient to line shifts elsewhere in the file.

**12.10 Provenance coverage (`complete | partial | illustrative`) and `--require-provenance`.** Every resolved program has a machine-readable provenance classification: `complete` (every normative rule is grounded, every declared `Document` is readable and matches any `SHA256` pin, and every `Clause` check passes without warning), `partial` (some provenance is declared or some rule/clause/document is incomplete, unread, or `STALE`), or `illustrative` (neither `Document` nor `Clause` is declared for the program's rules). Passing `--require-provenance` (or `//! require-provenance`) raises `CHR029` whenever normative rules are declared and provenance coverage is not `complete` (`docs/rfc.md` §4.5, §12.1, T08). `test/spec/spec_012_8_require_provenance.charter`, `spec_012_8b_partial_provenance_rejected.charter`

*Reused from v0.3:* the records `Clause`, `Span`, `Register` and the functions `covered`, `normsInterpreted`, `reverseProvenanceWith`, `stale`, `invalidated` in `src/Charter/Core/Provenance.lean` are the same definitions the v0.3 checker used (Law 13: one definition).
