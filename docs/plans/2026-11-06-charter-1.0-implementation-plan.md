## 1. Non-Negotiable Architectural & Process Rules

Every slice below is bound by `docs/mission.md`, `AGENTS.md`, and the 2026-11-06 rulings (`docs/rfc.md` §18.3):

1. **One unified language — strict superset of stratified eFLINT 4.1 (`Law 12`, `Law 13`, `D18`)**: Never split into `eflint-4.1-compat` vs. `charter-1.x-strict`. Parse single-word uppercase Charter keywords contextually so `.eflint` and `.charter` share one deterministic grammar. Keep `CHR020` rejecting cyclic self-negation in `Holds when`/`Derived from`; express defaults via stratified `Default`/`Priority` rules. Enforce project-level strictness (`--require-provenance`, `--require-complete-explore`, `--deny-warnings`) strictly as static gates that never alter runtime semantics.
2. **Minimal kernel-reducible `Core` vs. `lib/*.charter` ontologies (`Law 9`, `Law 10`, `D20`)**: Only irreducible primitives enter `src/Charter/Core/` (`Power` requiring `Valid when`, 4-valued `EvidenceStatus`/`Finding` on `Open` facts + `ReasonGraph`, stratified `Default`/`Priority` with `Conflict`, rule-level `Amend`/`Regime`, multi-doc SHA-256 `SourceRef`, and static `Money<CUR,SCALE>`/`Quantity<UNIT>` tags over `Int`). Contract lifecycles, agency mandates, monetary estates, and jurisdictional conflict policies ship in `lib/*.charter` (`Module`/`Use`) with proved module invariants (`D8`).
3. **One executable evaluator (`Law 9`)**: `Core/Transition.lean` and `Core/Derivation.lean` define transparent `Prop` relations; `Charter.Eval` is the **single** executable evaluator compiled into both `charter` and `charter-server`, proved sound and complete against those relations, using structural recursion with explicit fuel (never `partial`, `sorry`, `native_decide`, or extra axioms) so `charter prove` (`decide +kernel`) remains intact.
4. **The specification leads (`AGENTS.md`)**: Every surface or semantic change starts with its four-part decision brief (`D17`–`D27` where required), blessed `docs/spec/` wording, and a failing conformance fixture in `test/spec/` before touching compiler code.
5. **One logical change per commit**: Every numbered slice (`G0.1` … `G5.5`) lands as one atomic, fast-forward commit on `main` (or sub-commits where a slice separates spec/fixture from proof) with `tools/battery` green, `forM`/`mapM` in custom monads, capped `tools/kernel-probe` runs on kernel proofs, zero engine terms in CLI flags/diagnostics (`Law 11`), and an updated `HANDOFF.md` entry.
